首版目标同时支持 OpenCode、Codex、Claude Code。AgentFlow 管理通信与会话，主 agent 分配工作并检查结果。当前完成 Go S0 工程基础，真实通信与团队功能待后续阶段实现。

## A 配置启动什么

YAML/JSON 定义角色、工具、目录和嵌套分屏。示例使用三个角色。

| 角色 | 工具 | 会话模式 | 权限 |
|---|---|---|---|
| main | OpenCode | persistent | full |
| builder | Codex | fresh | full |
| reviewer | Claude Code | fresh | full |

columns 表示左右分屏，rows 表示上下分屏。运行使用配置快照，编辑后在下次启动生效。

## B 分屏之间怎样通信

```flow LR
配置文件 -> 协调进程: 启动计划
协调进程 -> cmux: 创建原生分屏
协调进程 -> [(SQLite)]: 保存消息与绑定
协调进程 -> 工具适配器: 投递通知
工具适配器 -> 原生会话: API、队列或 hook
原生会话 -> 协调进程: 接收确认与结果回复
```

收件人使用稳定角色地址。前后台必须对应同一会话。消息已保存、通道接受、会话投递和 agent 确认分别记录。

## C 下一项工作怎样开始

```sequence num
主 agent -> AgentFlow: assign，提供工作文件
AgentFlow -> 执行者: 按 fresh 配置开启新会话
执行者 -> AgentFlow: 角色与新会话就绪
AgentFlow -> 执行者: 发送本次工作内容
执行者 -> 主 agent: 结果报告与验证证据
```

persistent 模式保留原会话。普通 send 和当前工作的补充说明不触发重置。完成回报后，执行者等待下一次分配。

## D 上下文怎样保持精简

主 agent 维护背景、决策、进度和未完成事项。执行者读取必要文件，写独立结果报告。详细日志和原始证据通过路径引用。

新会话读取角色与工作包，不复制全部聊天。主 agent 核实结果后提炼合并文件摘要。

## E 故障与停止怎样处理

默认以最高权限启动本次会话。可恢复故障自动处理，依赖暂不可用时等待恢复。默认保持工具、模型和账号。

同一工作中断后优先恢复原会话。无法恢复时，核对检查点和产物，再继续剩余部分。

用户主动退出或关闭分屏会停止成员，系统通知主 agent。完成工作则继续待命。

```callout info 验收边界
三种工具的接收、重置、权限和恢复都需要真实验证。接口存在或命令成功退出，不能单独证明会话已经接收并执行。
```

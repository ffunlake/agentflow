## 实现

- `internal/runtime/snapshot.go`：版本 1 `RunSnapshot`、`SeatSnapshot` 和 `NativeBinding`。记录 run/agent/generation、tool/cwd/role/permissions/session、native session/workspace/surface 与 STARTING/READY 状态；保存完整冻结配置，验证 config digest、布局、seat 元数据、代际、状态与 native 绑定唯一性。初始 generation 为 1。快照 0600、父目录私有，完整写入后以同目录临时文件/hard link 独占发布；拒绝覆盖、symlink、公开文件/目录、未知字段与尾随数据。
- `internal/runtime/registration.go`：`Registry` 复用 `ipc.Actor`、IPC 错误码和现有 `store.CreateRun/CreateSeat`。先保存冻结配置和 digest；绑定 native 身份时仍为 STARTING。仅在收到匹配 run/agent/generation/tool/native/status 的 READY 后保存当前 seat，再更新内存状态。错误身份、过期/未来代际、未绑定 READY、重复绑定和重复 READY 均拒绝；并发重复只允许一次登记成功。写库失败不产生内存 READY。
- `internal/runtime/start.go`：`Launcher.Launch/WaitReady` 与 `Start`。校验完整启动计划后，写入私有快照，按 StartupPlan 的稳定 agent ID 顺序逐 seat 启动、等待、登记。LaunchRequest 明确传递独立 wrapper binary/argv、cwd/seat 元数据和 pane 路径；快照引用改为绝对路径，避免 agent cwd 改变引用含义。正文、role、model、工具 args 不进入 wrapper argv。Launch 返回 native 身份本身不构成 READY。
- 任一步失败立即停止后续启动，返回错误和初始化后的 registry；已确认 READY 的 seat 保留，未确认 seat 不写入为 READY。同一 artifact/store 的重新启动被拒绝，不盲目重放。无需新依赖、数据库迁移或新增业务表。
- 根 README 与 `internal/runtime/README.md` 记录 API、持久化模型和实际边界。原 `up --dry-run` 及非 dry-run 拒绝路径继续通过测试；本轮没有实现 `_seat`，该入口仍返回现有不支持参数错误，真实 `up` 继续明确报告 launcher / `_seat` 未实现。

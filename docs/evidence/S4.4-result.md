## 交付行为

隐藏 CLI `_seat --snapshot <absolute> --agent <id>` 已接入 `cli.Run`，不出现在全局帮助中。只接受这两个独立长参数、各一次、任意顺序。缺失/重复/未知参数、单横线别名、位置参数、`--`、`--key=value`、空值、NUL、相对快照和不合法 agent ID 返回退出码 2，无 stdout；诊断不回显原始参数。

`runtime.LoadStartupSeat` 复用 `ReadSnapshot`：要求已有私有目录与私有普通文件，拒绝直接符号链接、公开权限、未知 JSON 字段、尾随数据、坏摘要、run/agent/tool/cwd/role/permissions/session 元数据不匹配。入口额外要求全体 seat 为 STARTING、generation 1、空 native 身份；有效的运行态快照和其他正代际也不能授权本轮启动。不读取源 team 或 prompt 文件。

运行时失败在 stdout 输出 `{status:"FAILED",executed:false,error:{code,path,message}}`，stderr 保持 `agentflow: error:` 前缀，退出 1。稳定错误码：

| code | 条件 | path |
|---|---|---|
| `SEAT_SNAPSHOT_INVALID` | 文件、权限、编码、摘要、run/工具/cwd 等元数据校验失败 | `snapshot` |
| `SEAT_AGENT_UNKNOWN` | 合法格式但快照内不存在的 agent；runtime API 也拒绝不合法 ID | `agent` |
| `SEAT_STARTUP_INVALID` | 其余校验通过，但包含非初始代际、READY 或已有 native 绑定 | `snapshot.seats` |
| `SEAT_TOOL_ADAPTER_UNIMPLEMENTED` | 私有初始快照与 agent 校验通过 | `seat.tool` |

有效入口的完整 JSON 为：

```json
{"status":"FAILED","executed":false,"error":{"code":"SEAT_TOOL_ADAPTER_UNIMPLEMENTED","path":"seat.tool","message":"native tool adapter is not implemented; no tool was started"}}
```

该结果只表示校验通过后遇到未实现适配器。入口不查找或执行 opencode/codex/claude/cmux，不建立 IPC、写库或修改快照，也不生成 native 身份、READY 或 ACK。私有解码器错误被固定诊断替代，避免字段名或坏值携带凭据进入输出。

## cmux 纯函数与命令边界

`runtime.BuildCMUXCommand(plan, agentID, CMUXTarget)` 校验未执行的规范计划、冻结摘要、绝对快照引用与显式目标，返回 detached `CMUXLaunchCommand`：agent/tool/cwd/完整 PanePath、目标元数据、cmux binary/argv 和独立 wrapper binary/argv。篡改 wrapper、seat 顺序、布局、状态、cwd、tool、摘要、未知 agent 或非法目标均返回错误且不返回部分命令。纯函数不读文件、不查找工具、不执行命令。

使用已有静态证据而未重新执行 cmux：

- [cmux help](S1-probe-final/cmux-help.json)：`new-workspace --window ID --cwd PATH --focus false`；`new-split right|down --window ID --workspace ID --surface ID --focus false`；输出要求 `--json --id-format uuids`。
- [right split](S1-runtime-b7bf333c/codex-create-surface.json) 与 [down split](S1-runtime-b7bf333c/claude-create-surface.json)：已记录真实 argv 格式。

window 始终显式给定，只接受 UUID 或正确类型的 short ref；split 还需 workspace/surface。首个可见叶子的 PanePath 全为 child 0，用于构造新 workspace；新子树使用给定 SplitDepth 上的 child 1，其余子路径必须为 child 0，horizontal → right、vertical → down。未来 launcher 必须用返回且经核对的左/上兄弟 surface 作为锚点，并按视觉顺序创建布局，不能直接把 seat ID 排序当作创建顺序。纯函数无法证明目标在真实现场中的归属。

现有 cmux 的 `--command` 接收命令文本，并无已验证的 wrapper argv 传输接口；`new-split` 也无已验证的 cwd/ratio 参数。依据本轮“无 shell 拼接”，本实现不生成 `--command`、`sh -c` 或虚构的 argv/cwd/ratio 标志。wrapper binary/argv、split cwd 和完整比例保留为独立数据；此 builder 只构造拓扑命令，不实现 `Launcher`。真实 wrapper 传输、cwd/比例应用、cmux 创建、工具执行和 READY IPC 仍为 PARTIAL/UNIMPLEMENTED。

## 行为与边界

- assign 保存新工作意图，send 保存当前工作补充，reply 保存 reply_to 与报告状态并回复原 sender/generation。没有 tasks 表、accept/领取流程、当前工作状态机或 seat/generation 更新。
- StoreMessage 与 SaveOutbox 共用事务实现；新消息为 STORED，delivery 为 PENDING，channel 为 UNVERIFIED，attempt=0，reset_phase=NONE。MESSAGE_STORED 与正文、delivery 同事务提交。
- sender/request_id 正文逐字相同返回原 ID、路由及报告字段，不增加消息/delivery/journal；异正文返回 IDEMPOTENCY_CONFLICT。重试仍校验 caller 与原路由当前代际。
- ACK 核对 recipient/target generation，在同一事务更新 message.status 与 delivery.phase 为 ACKED，追加 MESSAGE_ACKED，JSON details 保存 request_id。同 key 重试不写入；不同 key 重复确认只追加 MESSAGE_ACK_RECORDED 请求凭据，返回首次确认事件。ACK 和消息 key 共享 sender/request_id 命名空间，跨操作或跨目标冲突拒绝。attempt/channel 不受 ACK 影响，确认仅表示显式 receipt。
- inbox 为只读一致快照，校验 run/current actor，按 seq 排序且限定目标代际，支持 after/pending，空结果为 []。查询不确认也不尝试投递。
- CLI 使用既有 state.db 与 XDG/--run-dir 目录，显式提供 --run/--agent/--generation；写请求需 --request-id，正文需 UTF-8 --body-file。支持 ack 与 message ack，reply --status 原样保存。成功 0、运行失败 1、用法错误 2；稳定 JSON 与 stderr code/path 诊断，错误不回显正文或 SQL。
- ValidateActor 可对接既有 IPC validator；事务内再次校验关闭代际竞争。当前 CLI 直接访问已有库，尚未接认证 coordinator 或自动环境身份。持久身份检查不证明原生会话身份认证或通信。

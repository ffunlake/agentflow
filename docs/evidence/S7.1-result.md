任务：s7-retry-policy。状态：本轮最小实现、fake/store 测试及全部指定工程检查 PASS（2026-11-03）。真实工具恢复为 UNIMPLEMENTED/UNVERIFIED，S7 整体 PARTIAL。

本轮新增 `internal/runtime/recovery.go` 的 RecoveryPolicy/RecoveryRunner、依赖 readiness probe 与 typed pre-action RecoveryError，以及 `internal/store/recovery.go` 的持久化 RetryDecision、分类、领取和完成事务。复用五张业务表；RECOVERY_DECIDED journal 保存首次冻结策略、尝试次数、下一次时间、分类、原因和对账证据，并原子更新 deliveries.next_retry_at。Recovery 尝试次数与 delivery.attempt（正文提交数）分离。

首次 tick 保存 WAITING，默认最多 3 次，等待 1s、5s、30s。到期 tick 独占领取，依赖必须明确允许；仍须通过 Reconcile、当前 native 绑定、可信输入及动作事务门禁。动作事务同时核对 recovery reservation 未被撤销。fresh reset 与独立 READY 合为一次动作，正文下一 tick 才可提交。等待期幂等，跨重开冻结预算；EXHAUSTED 保留原派发，不自动再开预算。缺少 probe 或 adapter 不伪造成功。

UNKNOWN_NEEDS_RECONCILE 保留原 native 请求，转 MANUAL_RECONCILE；旧代际拒绝自动重新定位；stop/权限/配置错误/取消停止自动推进。调用 context 始终传给 probe/native adapter，取消凭据使用最多 5 秒独立 context 落盘。崩溃遗留 ATTEMPT_RESERVED 的 classification 为 NEEDS_MANUAL_RECONCILE，后续 tick 不抢占。COMPLETE 仅表示已有 SENT/ACKED 证据，不表示任务完成或真实工具恢复。

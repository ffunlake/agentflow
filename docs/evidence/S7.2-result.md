# S7.2 原会话优先与安全重绑定结果

本轮局部实现：完成最小 SessionRecovery/BindingRecovery API 和 fake adapter/clock 验证。S7 整体仍为 PARTIAL；真实 opencode/codex/claude/cmux、真实 READY/权限、原生检查点注入和 S7.3 完整故障矩阵未执行。

实现入口：

- `internal/runtime/binding_recovery.go`：SessionRecovery、BindingRecoveryAdapter、InspectOriginal/Create/WaitBindingReady、NoteExit 和完整 native 事件 ValidateBinding。
- `internal/store/binding_recovery.go`：持久 BindingRecovery 领取/完成、S5.3 账本对账、LAUNCH_REQUESTED/LAUNCH_BOUND、BINDING_CHANGED 历史、退出/拒绝事件、跨 request/进程的有限预算和 CAS。
- `internal/runtime/start.go`、`registration.go`：Launch 前保存请求，native 返回后保存绑定；READY 仍独立确认；迟到启动注册遵守 stop/关闭/恢复门禁。
- `internal/store/session.go`、`reconcile.go`、`recovery.go`：S5 原生动作和 S7.1 恢复共同读取绑定恢复/主动关闭/未知退出门禁。

核心约束：

1. AVAILABLE 原 native 保留原 generation 和绑定；位置变化只允许原 native、相同逻辑身份和新位置 READY，旧位置保留在 journal。
2. UNAVAILABLE 必须是针对原绑定的可信观测；S5.3 对账与 S6.3 文件检查点通过后，先持久 CREATE_REQUESTED，再创建并等待新 READY，最后原子推进下一 generation。
3. 权限和完整冻结配置摘要同时校验；创建请求携带冻结角色/模型/参数及文件检查点。恢复 API 没有 reset、正文投递或 ACK 操作。
4. USER_CLOSED、STOP_REQUESTED、已确认终态阻止复活；未知原因记录 EXIT_UNVERIFIED，进入 MANUAL_RECONCILE；旧位置/代际事件拒绝并去重审计。
5. 原始策略、预算、等待、未决领取和创建意图跨重开保留。不同 request 不能抢占或扩大同 agent/generation 预算；已确认或未知动作均不重放。
6. 部分启动的 LAUNCH_BOUND 经原会话检查和 READY 补齐同 generation；仅 LAUNCH_REQUESTED 且 native 响应丢失时保持未知，不重新 Launch。尚未开始的角色由启动流程继续管理，本 API 不创建新团队。

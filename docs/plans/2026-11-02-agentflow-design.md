# AgentFlow 架构设计 v2

状态：依据 grill-me 已确认结论修订；S0 工程基础使用用户指定的 Go，真实通信尚未验收。

需求依据：[访谈决策记录](2026-11-02-agentflow-interview-decisions.md)。工程选择以技术实现文档为准。

## 1. 已确认目标

使用 YAML/JSON 定义角色、终端工具、工作目录和嵌套分屏，通过命令在 cmux 启动。首版同时支持 OpenCode、Codex、Claude Code，保留原生终端界面；投递和展示必须属于同一会话。

AgentFlow 负责启动、通信、接收确认、状态观察和恢复。主 agent 负责判断工作可行性、分配工作、检查结果及决定下一步。执行者完成并回报后等待下一次分配。

默认最高权限，作用于本次启动的会话。已确认可行的工作自主推进；可恢复故障自动处理，依赖暂不可用时等待恢复后继续。恢复沿用配置的工具、模型和账号。

## 2. 架构与通信模式

采用中心消息代理和异步持久队列。逻辑上允许任意成员点对点通信；物理上经过本机协调进程。

```text
YAML/JSON → CLI → 协调进程 → SQLite
                    ├→ cmux 嵌套分屏
                    └→ 工具适配器 → 原生会话
原生会话 → 接收确认/结果消息 → 协调进程 → 收件人
```

按用户指定采用 Go 1.25+、Go modules、纯 Go SQLite 驱动；后续使用 Unix socket。配置解析和校验库在 S2 按既有契约选型。每个团队运行有独立账本和身份，默认不引入外部服务。

消息保存成功、通道接受、交入会话、agent 明确确认分别记录。消息已读不能证明工作完成；主 agent 根据结果文件与验证证据判断完成。

## 3. 配置与布局

完整示例见 [YAML](../../examples/team.yaml) 与 [JSON](../../examples/team.json)。示例 main 使用 OpenCode、builder 使用 Codex、reviewer 使用 Claude Code。

根配置包含 version、name、terminal、lead、context_dir、defaults、agents、layout。lead 指定主 agent。defaults 提供 tool、cwd、permissions、session；单个角色可覆盖。

permissions 默认 full；session 默认 fresh。示例主 agent 显式设为 persistent，执行者继承 fresh。所有角色都有稳定 ID、role 和 prompt 或 prompt_file。

layout 为嵌套二叉树：columns 表示左右，rows 表示上下；ratio 为首个子区域占比，默认 0.5。叶子引用 agent ID，每个角色恰好出现一次。身份不依赖分屏位置。

相对路径以配置文件目录为基准。CLI --tool 只覆盖默认工具，角色显式工具优先。配置启动时冻结，恢复沿用快照，修改在下次启动生效。

## 4. 新工作与会话

主 agent 通过一次 assign 操作派发下一项工作。fresh 模式自动完成：确认执行者已结束上一项工作 → 开启新会话 → 重新注入角色和必要文件路径 → 确认就绪 → 发送工作内容。

persistent 模式保留会话。send 用于当前工作的补充或普通交流，不触发重置。不要求用户维护工作 ID、领取凭证或操作强制任务状态机。消息内部 ID 仅用于投递确认和恢复去重。

重置可使用工具的 /new、/clear 或等价接口，但必须验证原生分屏已经切换。不能将重置命令作为普通消息交给模型；存在运行命令或用户输入草稿时排队。

同一工作中断时优先恢复原会话。只有新工作才默认新建会话；恢复不能盲目重做整项工作。原会话不可恢复时，主 agent 核对检查点和实际产物后继续剩余部分。

## 5. 文件上下文

主 agent 管理精简的项目背景、决策、进度和未完成事项。执行者读取本次工作包与必要文件，写独立结果报告，主 agent 核实后提炼合并。详细日志和原始证据通过路径引用。

context_dir 下按 run ID 分目录，避免不同运行共同写同一进度文件。新会话读取角色文件、摘要和本次输入，不复制全部历史聊天。主 agent 也须能通过文件恢复上下文。

## 6. 三种工具接入

| 工具 | 接入候选 | 必须验证 |
|---|---|---|
| OpenCode | 每角色 serve、确定 session、原生 attach、session API | 空闲接收、会话切换、目录和权限一致 |
| Codex | 原生 queue --resume 或 app-server 与原生 TUI 连接 | 实际唤醒、同 thread 展示、重置后路由 |
| Claude Code | cmux wrapper、原生消息 hook、原生会话重置 | 唤醒、重置完成信号和角色重新注入 |

本机 Codex 0.166.0 已提供 queue --resume 与 --remote。恢复失败时 queue 仍可能成功退出，因此退出码不代表已唤醒。首版必须验证 Codex 主动接收，不能把延迟模式当作完整支持。

## 7. 自主恢复与停止

程序故障触发重连、会话恢复和状态对账；采用退避等待，不因固定重试次数用尽就结束工作流。无法立即恢复时显示准确原因，依赖恢复后继续。

投递结果不明时先查证，不能为保持运行而盲目重复执行。缺少登录、额度或外部必要信息时通知用户并保留待恢复状态。最高权限不能替代外部依赖。

用户主动退出成员或关闭分屏，视为停止该成员，通知主 agent，不自动复活。无法识别退出原因时记录不确定性并核对。stop 明确停止整个运行，完成工作则继续待命。

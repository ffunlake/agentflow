# Explicit native SubmitAdapter

Scope: an opt-in Go `SubmitAdapter` for one already registered OpenCode/Codex generation/session, using foreground CLI resume and the existing SessionCoordinator. This follows task `native-submit-adapter`; no CLI/default coordinator wiring is added.

`NewNativeSubmitAdapter(NativeSubmitOptions)` binds a complete READY `SeatSnapshot`, matching frozen `config.ResolvedAgent`, an absolute native executable and a mandatory `NativeSubmitGuard`. `NativeCommand` remains the owner of format, cwd, permissions, model and permitted extension flags. OpenCode adds `--session <id>`; Codex inserts `resume <id>` before the final stdin `-`. Raw flags and cmux CLI shims are rejected. Command arguments are detached at construction.

SessionCoordinator supplies the current identity from the store, commits `SUBMIT_REQUESTED` and increments the attempt before calling Submit. Submit checks the configured actor/generation/tool/native binding and message route, then acquires the exact binding's input guard. The guard must verify the input and hold exclusive ownership until release after the process exits and the result is parsed. Busy, draft, incomplete input, mismatched identity, unknown inspection or missing ownership fail closed. Implementing safe TUI ownership is the embedding process's responsibility; no permissive production guard is provided.

The frozen message body is the entire stdin, byte-for-byte. No shell, prompt-file write, extra instructions or acknowledgement challenge is used. Child cwd, timeout/cancellation, bounded stdout/stderr and reaping reuse `captureNative`. The caller supplies a bounded context. Native stderr and event content never enter errors.

A zero exit is insufficient. JSONL must identify the exact existing session and contain assistant output followed by a completed turn (`thread.started` / `item.completed` / `turn.completed` for Codex; session-bearing `text` / `step_finish` with reason `stop` for OpenCode). Identity changes, malformed events, empty/lost output, missing assistant/completion, truncation and cancellation yield UNKNOWN. Explicit native failure events yield FAILED; neither result authorizes replay. Any adapter error retains the existing coordinator's `SUBMIT_REQUESTED` / `UNVERIFIED` behavior. Success returns the guard-verified actor and native binding with a tool-specific CLI channel; it does not manufacture an ACK, role result or native acceptance report.

Verification uses a Go executable fixture, temporary directories and SQLite, with no model CLI request, network request or user window operation. Tests cover exact argv/cwd/stdin, permission flags, constructor/boundary identity checks, input protection, failure and missing output, cancellation, bounded capture and coordinator no-replay/frozen-body behavior.

Continued TUI operation and multiple windows with persistent agent sessions remain UNIMPLEMENTED. This adapter does not implement ResetAdapter, native input ownership, scheduling, background services, live window binding or automatic generation rebinding. A new generation/session needs a newly authorized adapter. Fixture success is not native PASS; installed CLI help only establishes advertised argument syntax.

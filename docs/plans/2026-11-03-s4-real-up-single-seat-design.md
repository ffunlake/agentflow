# Single OpenCode foreground up

`up -f CONFIG --run ID [--run-dir DIR] --window REF --workspace REF --surface REF` supports exactly one OpenCode foreground seat. It stays in the foreground as the existing coordinator after the startup handshake. `--dry-run` remains a pure plan for all supported configurations. Other real layouts/tools return structured PARTIAL/UNIMPLEMENTED without initializing state.

After validating the plan and explicit options, create only directory scaffolding, then acquire the existing unique run lock. Under that lock exclusively publish a durable attempt marker before opening/migrating a new store. Any prior attempt, database, snapshot or native evidence blocks startup; failed or canceled attempts are never overwritten or replayed. The lock is held through initialization, native startup, READY registration and coordinator IPC serving.

Reuse Compile/Start/ForegroundLauncher. A small launcher wrapper creates the private run/agent file context from Start's frozen snapshot before calling the foreground adapter. Installed OpenCode emits native JSONL; exact completed assistant actor/generation/tool/nonce plus independently collected native/session/location IDs are required. Extend Registration with the verified nonce and atomically save a STARTUP_READY_VERIFIED journal proof together with the current READY seat, without a schema change. Nonce-free low-level fake/legacy registration keeps its existing API semantics; real up requires a nonce.

Start returns a structured result with run/artifact/context/evidence paths and persisted READY proof. Bind the existing coordinator IPC socket on the same store and lock, print readiness, then serve until SIGINT/SIGTERM. Startup has a bounded context; serving uses the enclosing process context. Errors retain artifacts, close owned resources and release only the acquired lock. A successful foreground native handshake has already exited: neither READY nor coordinator availability claims a persistent native TUI, effective permissions, native submit/reset, process attach/stop or recovery.

Offline validation uses fake launchers and real wrapper/native-fixture subprocesses for success, lock contention, failures, target mismatch, absent/incorrect READY, cancellation, IPC and duplicate up before/after reopening. One installed OpenCode process is authorized in one new temporary pane, outside protected surfaces 1000060034/35; Codex/Claude are not launched. Field evidence independently reparses saved JSONL and reopened SQLite proof. Required test/build/check/tidy commands run after implementation.

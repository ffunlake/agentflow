# S6.1 按 run 隔离的文件上下文实施计划

任务：`s6-context-base`；session：`61f003e8-1ba7-4a0b-94b9-b72fe43a2c3d`。

## 目标与设计

使用标准库新增 `internal/context`，在绝对、规范、无 symlink 的 context_dir 下排他创建 `<run_id>/`，并创建每个 agent 的私有目录。run 描述绑定路径、run、lead、agent 集合和冻结配置摘要；所有入口重新核对目录权限与描述，避免旧句柄误写被替换的目录。Go `os.Root` 将文件操作限制在已打开的目录内。

选择每 agent 不可变 revision 加 manifest 的方案：与原地替换五个独立文件相比，manifest 最后原子发布可防止读到混合版本；与数据库保存完整上下文相比，它不增加 schema 或依赖，并保留直接可查的文件产物。调用者显式读取 revision，不猜测 latest。每次发布排他创建 revision 目录，文件经同目录临时文件、fsync、hard-link 无覆盖发布，manifest 是提交点。中途失败保留未提交目录，读回报错，重复 revision 明确冲突。

每版包含 role/background/decisions/progress/pending 五个版本化 JSON 文件，以及精简 manifest（相对路径、用途、SHA-256、更新时间）。正文和引用均限制大小；角色协议引用冻结运行快照中的 prompt，并记录摘要，原始 prompt_file 只存在于既有冻结配置，不被重新读取。身份、版本、文件集合、路径、未知字段、尾随数据、摘要、权限与 symlink 均严格校验。

## 实施顺序

1. 实现目录与文件安全辅助、run 描述、绑定 agent API、不可变发布与完整读回校验。
2. 增加 runtime 桥接：消费现有 RunSnapshot 文件，为每个 agent 发布初始角色与空摘要。S5 消息、报告和代际仍由现有 store 管理；S6.1 不合并报告或重建会话。
3. 增加单元测试与双 run/双 agent 集成测试，覆盖跨身份、损坏、权限、重复、并发、symlink、未知字段和源 prompt 变更。
4. 同步 README、API 说明、总实施计划和 `docs/evidence/S6.1-result.md`。
5. 运行 gofmt、`go test ./...`、`go build ./...`、`make check`、`go mod tidy -diff`；记录真实结果并执行指定 handoff。

## 验收边界

本轮是个人/小团队同一 OS 用户下的 API 身份隔离；文件权限不提供对同一用户恶意进程的身份认证。SHA-256 校验检测损坏，不提供签名认证。未提交 revision 保持失败可见；无自动清理或恢复。真实工具注入、cmux、三工具、S6.2 报告合并、S6.3 会话重建与 wiki 均不在范围内。

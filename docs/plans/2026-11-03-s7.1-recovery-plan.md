# S7.1 最小有限恢复实施计划

本轮范围由 s7-retry-policy 明确限定为最小策略、有限退避与依赖等待。采用 runtime RecoveryRunner 显式 tick，加已有 journal/ delivery.next_retry_at 保存决策；复用 S5 的对账、输入检查与原子动作门禁。相比后台 timer/scheduler，这个入口可用注入时钟确定性验证，不增加生命周期或任务表；相比仅扩充 resume 查询，它能在依赖明确允许时推进一次已有动作。

- [x] 定义有限 RecoveryPolicy，默认最大 3 次，等待 1 秒、5 秒、30 秒；分类可恢复、依赖不可用、不可恢复、需人工对账。
- [x] 在原有 SQLite immediate 事务内对账、冻结首次策略、持久化等待/领取/结果及 next_retry_at；等待和终态重复调用幂等，跨重开不重置预算。
- [x] 执行前检查 stop、旧代际、未知结果、权限/配置错误及 context；依赖 probe 明确允许才继续。动作领取事务额外核对恢复 reservation，防止被撤销的旧调用执行。
- [x] fresh reset+独立 READY 与正文提交分为不同 tick；未知请求不重放，不自动 ACK。中断的恢复 reservation 保留人工对账分类，不抢占，不新增恢复会话语义。
- [x] fake adapter + 时钟测试连续失败、依赖恢复、取消、stop、次数耗尽、未知结果、数据库重开、独立句柄并发、撤销竞争、旧代际和 journal 事务回滚。
- [x] README/runtime 契约、总实施计划及 S7.1 结果文档。
- [x] 完成 gofmt、go test ./...、go build ./...、make check、go mod tidy -diff；新增恢复路径 race 检查通过。实际结果见证据报告，DONE handoff 已发送并确认。

没有新增 recover/retry CLI：目前缺少真实依赖/native adapter 接线，runtime API 足以验收本轮；现有 reconcile/resume CLI 不赋予执行权限。S6.3 Bootstrap/Rebuild 保持文件上下文能力。真实原生会话恢复、主动关闭语义、包装器恢复与完整故障矩阵留在原 S7.1 未完成出口及 S7.2/S7.3；工具、模型、账号沿用已有冻结绑定。
